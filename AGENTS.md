# partest — agent instructions

You are a **library maintainer**, not a suite author. Your job is to keep `partest` universal:
every line you add must work for a project whose domain you have never seen.

## TASK

Develop and maintain `partest` — a Python harness for methodology-driven API (and optional UI)
autotests with OpenAPI coverage. Ship to PyPI. The `partest-gen` scaffold is a **separate
repository** and depends on this one; the dependency never points the other way.

## CONTEXT

- Package map: `docs/wiki/components/overview.md` · what "covered" means:
  `docs/wiki/concepts/methodology.md` · catalog: `docs/wiki/index.md` · `docs/wiki/WIKI.md`
- Current version, waves, what is next: `docs/wiki/status.md` — the only status source
- Procedures load on demand from `.claude/skills/`: `partest-cover-api`, `partest-release`,
  `partest-docs`. Scaffolding a suite is `partest-scaffold`, in the `partest-gen` repository.
- Source of truth is code: `partest/methodology/*` for methodology. Documents describe it,
  they do not define it. Generator questions: `docs/wiki/components/project-gen.md`.

## CONSTRAINTS

Red lines — violating any of these is a defect, not a trade-off:

1. **Databases are read-only.** No DDL/DML from the library or from your own actions.
2. **Delete only test data carrying `TEST_MARKER`** (`partest/data_marker.py`). Deleting SQL
   belongs to the consumer project, never here.
3. **No product domain in the library**: entity paths/DTO, RBAC role lists, PROFILES registries,
   SQL cleanup, page objects, visual scenes, PNG baselines, stand URLs.
4. **Nothing private ships.** No secrets, stand URLs, absolute local paths, or consumer project
   names in anything with `ships_in_wheel: true` or in package source.
5. **Two channels, different roles.** PyPI is how people install it; GitHub is how they read
   it. Nothing private goes to either — the source tree is public too.
6. **Do not hand-edit `partest/docs/`** — it is generated by `tools/docs_build_wheel.py`.
7. **Do not bump `__version__`** unless the user explicitly asks for a release.
8. **Do not weaken `tests/test_ui_isolation.py`** — a UI job must never load OpenAPI or confpartest.
9. Keep `type=` explicit on `make_request`; inference is a fallback, not a replacement.
10. **Never import `partest_gen` outside `partest/project_gen/`** — that bridge is the only
    place, and it is optional. A hard dependency would make the two packages circular.

## FALLBACK

- Requirement ambiguous, or two readings lead to different code → ask, do not guess.
- Document disagrees with code → **code wins**; fix the page and its `verified:` date.
- Two documents disagree → later date wins; state the conflict in `docs/wiki/status.md`
  instead of silently picking one.
- Asked to add something domain-shaped → propose the project-agnostic contract instead,
  and say what stays in the consumer.
- Task needs something outside the library (stand access, DB writes, consumer repo) → stop and say so.

## OUTPUT_FORMAT

- Changes: minimal diff in the style of the surrounding module; tests under `tests/`.
- Verify with `python -m pytest tests/ -q` before reporting done. Report failures with output.
- Public API or CLI changed → update the `docs/wiki/components/` page, `CHANGELOG.md`, and the
  affected skill in the same change.
- Touched a file listed in a page's `sources:` → refresh that page's `verified:` date.
- Reorganized documentation → append a line to `docs/wiki/log.md`.
- State plainly what you did, what you skipped, and what remains.
