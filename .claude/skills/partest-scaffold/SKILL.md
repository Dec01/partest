# Scaffolding a suite with partest-gen

## When to use this

- Greenfield: an OpenAPI spec exists, no test project yet
- Adding an isolated UI suite to an existing generated project
- Re-syncing generated resources after the spec changed

**Not this skill:** writing or improving tests in an existing suite → `partest-cover-api`.

## Commands

```bash
partest-gen from-openapi ./my-suite --file openapi.yaml --depth p1 --force --with-ui
partest-gen init-ui      ./my-suite --force
partest-gen sync-openapi ./my-suite --depth p1
partest-gen dump-ir      openapi.yaml -o .partest/suite_ir.json
```

| `--depth` | Generates |
|---|---|
| `resources` | paths + collection façades |
| `default` | + payloads, validations, Default and NotAllowed tests |
| `p1` | + full P1 stubs per subtype + `P1_CHECKLIST.md` |

UI is orthogonal to depth: `--with-ui` at generation time, or `init-ui` on an existing project.
For greenfield prefer `--depth p1 --with-ui`.

## The generated-file contract

Files carrying the `AUTO-GENERATED by partest-gen` banner are overwritten by `sync-openapi`.
Files without it are yours and are skipped unless `--force`.

**Never hand-edit a banner file** — put your code in the non-generated modules next to it, or the
next sync silently discards your work.

## After generation — the loop

Full checklist: `references/post-gen-playbook.md`. Short form:

1. **Read the maps** — `.partest/openapi_summary.md`, `src/api/tests/<tag>/P1_CHECKLIST.md`
2. **Wire** — `.env` (base URL, OIDC), `roles.py` → `TokenManager` in the API conftest
3. **Order by impact** — auth / money / PII writes before catalog GETs
4. **Per endpoint** — unskip the stub → seed data or `add_url1` → correct `type=` →
   status + schema + value assertions. Vertical case for create/update. IncorrectBody only
   through `ApiClient` with `content=`
5. **Measure** — run the suite, then `test_zorro`, then close `missing_p1` (serially — not `-n`)
6. **Sync** — `partest-gen sync-openapi … --depth p1` after spec changes
7. **UI as a separate job** — login page object, API seeding, smoke, then baselines:

```bash
python -m partest.ui.capture_baselines --out src/ui/baselines/reference \
  --scenes src/ui/tools/scenes.example.json --dry-run
```

Use the generated façades rather than raw strings: `models.<tag>.paths.*`, `.payload.*()`,
`.validate.*`, `.headers.read|write`.

## Isolation rule (do not break this)

`src/ui/conftest.py` must **never** import `confpartest`, load OpenAPI, or start the API coverage
session. A UI job that pulls the API session becomes slow, network-dependent and flaky. The
library enforces its half with `tests/test_ui_isolation.py`; the project must hold its half.

## Definition of done for a slice

- [ ] P1 cases present for the chosen endpoints with correct `type=`
- [ ] Vertical case wherever create/update exists
- [ ] `missing_p1` empty for those endpoints in a serial run
- [ ] Cleanup through the tracking registry; test data carries the marker; no secrets committed
- [ ] UI isolation intact; reference baselines committed only once selectors are stable

## Known limits

- The classifier is heuristic: check subtypes on unusual paths before trusting the stub set.
- `sync-openapi` only refreshes banner files — restructured hand-written tests are your problem.
- Generated payloads are shape-correct, not domain-correct: required business values are yours.
