# WIKI.md — схема документации partest

Этот файл описывает, **как устроена** документация. Содержания знаний здесь нет.
Читается один раз перед правкой доков; в обычной работе не нужен.

## Три слоя

| Слой | Где | Кто владеет | Правило |
|---|---|---|---|
| **Raw** — неизменяемые источники | вне репозитория | человек | снапшоты источников хранятся рядом с репозиторием, а не в нём — см. ниже |
| **Wiki** — производное знание | `docs/wiki/` | агент | создаёт страницы, обновляет, чинит перекрёстные ссылки |
| **Схема** — конвенции | этот файл + `AGENTS.md` | человек + агент | эволюционирует медленно, правится осознанно |

Вытесненные страницы и снапшоты источников **не публикуются**: они описывают внутреннюю
кухню консьюмер-проектов — продуктовые сущности, роли, инфраструктуру. Репозиторий публичный
([[decisions/pypi-only]]), поэтому этот слой лежит рядом с ним локально и закрыт `.gitignore`.

## Структура wiki

```text
docs/wiki/
  WIKI.md        схема (этот файл)
  index.md       каталог: одна строка на страницу — точка входа для агента
  log.md         хронология операций ingest / update / lint
  status.md      ЕДИНСТВЕННЫЙ источник статусов, версий, волн, «что дальше»
  concepts/      методология: почему так, инварианты предметной области
  components/    модули библиотеки: что делает, где код, публичный контракт
  howto/         рецепты для человека: пошагово, с рабочим кодом
  decisions/     ADR: решение, контекст, последствия, дата
```

Выбор категории: `concepts` — «почему», `components` — «что есть», `howto` — «как сделать»,
`decisions` — «почему именно так, а не иначе».

## Frontmatter — обязателен на каждой странице

```yaml
---
title: Coverage matrix (subtype × TC)
status: current            # current | draft | stale | archived
verified: 2026-09-04       # дата последней сверки с кодом
sources: [partest/methodology/matrix.py]   # файлы кода, от которых зависит страница
audience: agent            # user | maintainer | agent
ships_in_wheel: false      # true → страница уезжает в PyPI-колесо
---
```

`sources` — центральный механизм. `tools/docs_lint.py` сравнивает дату последнего коммита,
затронувшего файлы из `sources`, с `verified`. Если код новее — страница помечается **stale**.
Так документация не молча гниёт в горячей фазе разработки, а сама сообщает о расхождении.

Правило: если страница описывает поведение кода — у неё **должен** быть непустой `sources`.
Страницы `decisions/` и `howto/release` могут иметь пустой `sources`.

## Ссылки

- Внутри wiki: `[[howto/quickstart]]` — путь от `docs/wiki/` без расширения.
- На код: обычная markdown-ссылка на путь от корня репозитория, при желании с `:строкой`.
- Наружу: только публичные URL. Приватные пути (`C:\…`, UNC, URL стендов) — запрещены везде,
  в страницах с `ships_in_wheel: true` это ошибка линтера.

## Версии

Единственный источник версии — `partest/__init__.py` (`__version__`); `setup.py` читает его.
Литерал версии допустим только в `status.md`, `CHANGELOG.md` и `docs/PYPI.md`.
В остальных страницах пишем «текущий релиз — см. [[status]]».

## Рабочие циклы

**Ingest** — появился новый источник (снапшот бэклога, релизные заметки, разбор инцидента):
положить в локальный `docs/raw/<источник>/<дата>/` (он в `.gitignore`), разнести выводы по
страницам wiki, добавить строку в `log.md`. Источник не редактируем и **не публикуем** — в wiki
попадает вывод, а не чужой внутренний документ.

**Query** — вопрос: `index.md` → 1–2 страницы. Если ответа не нашлось, но он был получен из кода —
завести страницу, чтобы следующий раз обошёлся без раскопок.

**Lint** — `python tools/docs_lint.py`: битые ссылки, протухшие `verified`, литералы версий,
приватные пути, дрейф `docs/wiki` ↔ `partest/docs`. Запускается и внутри `pytest tests/test_docs.py`.

## RAG — когда включать

Сейчас RAG **не используется**: корпус мал, `index.md` + grep точнее и дешевле эмбеддингов.
`tools/docs_index.py` уже собирает машинный `index.json` (заголовки, якоря, `sources`, размеры),
корпус нарезаемый по заголовкам — то есть подготовлен.

Включать векторный индекс, когда выполнится хотя бы одно:

1. wiki > ~60 страниц или > ~15 000 строк;
2. появится сопоставление «код ↔ документы аналитики» (много источников, слабые ключевые слова);
3. локальный слой источников вырастет так, что поиск по нему перестанет укладываться в контекст.

Тогда: `tools/rag_index.py` читает тот же `index.json` и строит локальный индекс. Wiki при этом
остаётся первичной — RAG ищет по локальному слою источников, а не подменяет курируемые страницы.

## Инварианты правки

1. Ни один файл не удаляется молча: либо `git mv`, либо запись в `log.md` с указанием преемника.
2. Один факт живёт в одном месте; остальные ссылаются на него.
3. Статус, версия, «что дальше» — только в `status.md`.
4. Меняешь публичный API или CLI — обновляешь: страницу `components/`, `CHANGELOG.md`, скилл.
5. Каждая заметная правка — строка в `log.md` (дата, что сделано, какие страницы затронуты).
