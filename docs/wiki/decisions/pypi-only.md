# ADR: дистрибуция только через PyPI

**Дата:** зафиксировано в 1.4.0, подтверждено 1.5.0.

## Решение

Единственный публичный канал — PyPI: `pip install partest` / `pip install partest[ui]`.
Публичный GitHub-репозиторий **не планируется**. Дерево исходников не выкладывается.

## Следствия

1. **На странице PyPI не работают относительные ссылки.** Некуда вести — публичного зеркала
   исходников нет. Поэтому `long_description` (`docs/PYPI.md`) самодостаточен, а полная
   документация едет внутри колеса и открывается через `python -m partest.docs`.
   См. [[decisions/docs-in-wheel]].
2. Не добавлять публичный CI, бейджи, issue-шаблоны, ссылки на GitHub Actions.
3. Всё, что попадает в колесо, читают посторонние → никаких приватных путей, URL стендов,
   внутренних ID волн и имён консьюмер-проектов.
4. Обратная связь и баг-репорты приходят вне репозитория; трекером служит [[status]].

## Почему так

Библиотека вырастает из внутреннего харнесса, и её бэклог завязан на консьюмер-проект. Публикация
дерева потребовала бы отдельной работы по вычистке истории и постоянной синхронизации двух
источников правды. Пакет на PyPI даёт потребителю всё нужное; исходники ценности без контекста не
добавляют.

## Что именно публикуется

Проверять надо содержимое артефактов, а не намерение. Итог аудита 2026-09-04:

| Артефакт | Что внутри |
|---|---|
| wheel | `partest/**` (код, `py.typed`), 14 страниц `partest/docs/*.md`, метаданные |
| sdist | то же плюс `CHANGELOG.md`, `setup.py`, `setup.cfg`, `MANIFEST.in`, `PKG-INFO` |

**Не публикуется** и явно вычищено в `MANIFEST.in`: `tests/` (называют консьюмер-проект
и его сервисы, плюс половина требует `tools/`, `docs/wiki/`, `.claude/` — из sdist они
всё равно не прошли бы), `docs/` целиком (wiki, снапшоты `raw/`, архив), `tools/`,
`.claude/`, `.grok/`, корневой `README.md` (обращён к репозиторию и ссылается на то,
чего в пакете нет).

Проверки, которые это удерживают: `tests/test_docs.py` —
`test_nothing_published_names_the_consumer_project`,
`test_manifest_excludes_the_repository_only_material`,
`test_shipped_docs_do_not_point_at_repository_paths`.

## Открытые вопросы публикации

1. **Нет файла `LICENSE`.** MIT заявлен в классификаторах `setup.py` и в `docs/PYPI.md`,
   но текста лицензии в репозитории нет, и сборка каждый раз пишет
   `warning: no files found matching 'LICENSE'`. Пакет объявляет лицензию, которую не
   прикладывает. Файл с именем правообладателя и годом — решение владельца.
2. **`TEST_MARKER` по умолчанию — `"AQA"`** (`partest/data_marker.py`, шаблон `.env` в
   `project_gen/skeleton.py`). Это уже не проза, а поведение: у постороннего проекта
   тестовые данные по умолчанию называются именем чужого проекта. Смена дефолта меняет
   то, какие строки найдёт очистка delete-by-marker у существующих потребителей, —
   поэтому мажорная версия, а не патч.

## Что изменит решение

Появление внешних контрибьюторов или требование аудита исходников. Тогда нужен отдельный публичный
репозиторий с вычищенной историей, а не «git push» этого дерева.
