# ADR: документация внутри колеса, `partest/docs` генерируется

**Дата:** 2026-09-04 (заменяет ручное копирование, введённое в 1.4.0).

## Контекст

Публичного зеркала исходников нет ([[decisions/pypi-only]]), поэтому единственный способ отдать
пользователю документацию — положить её в колесо. В 1.4–1.5 это делалось **копированием руками**
из `docs/` в `partest/docs/`. Последствия, зафиксированные до реорганизации:

- в колесо уезжали внутренние русскоязычные файлы: статус внедрения в консьюмер-проект, волны
  W1–W4, релизный чек-лист с внутренними ID;
- дисциплина «не забудь скопировать» держалась только на строчке в гайде для мейнтейнера;
- `docs/README.md` служил `long_description` и содержал 14 относительных ссылок, которые на
  странице PyPI ведут в никуда.

## Решение

1. `partest/docs/` **генерируется** из `docs/wiki/` скриптом `tools/docs_build_wheel.py`.
   Руками не редактируется; в шапке каждого сгенерированного файла стоит предупреждение.
2. Что уезжает, решает поле `ships_in_wheel: true` во frontmatter страницы. По умолчанию — `false`.
3. Внутренние ссылки при генерации разворачиваются в плоские имена файлов, frontmatter срезается.
4. `long_description` — отдельный самодостаточный `docs/PYPI.md`, а не пользовательский README.
5. Доступ к докам после установки: `python -m partest.docs list | show <page> | path`.
6. Расхождение `docs/wiki` ↔ `partest/docs` — ошибка линтера и падение `tests/test_docs.py`.

## Следствия

- Перед релизом обязателен `python tools/docs_build_wheel.py`; проверка — `--check` в CI-шаге.
- Внутренние страницы (статус, ADR, бэклог, снапшоты `docs/raw/`) в колесо не попадают никогда.
- Пользователь получает согласованный набор: quickstart, migration, cookbooks, методология.

## Альтернативы, которые отклонены

- **Ссылки на внешний сайт документации** — нет публичного хостинга и нет желания его вести.
- **Оставить ручное копирование** — уже дало утечку внутренних доков в публичный пакет.
- **Пакетировать всю `docs/wiki`** — тогда посторонние читают внутренний бэклог и статусы.
