This document is the **continuation guide** for maintainers and AI agents after
the 1.0 harness + G1–G5 generator land.

## Public invariants

1. **No product domain** in the library (entities, RBAC matrices, stand URLs).
2. **No private absolute paths** in package or public docs.
3. **Consumer config** stays in `confpartest.py` / `.env` of the suite project.
4. Prefer **canonical** TC names (`request_default`); keep legacy aliases.
5. Keep `type=` on `make_request` until inference is ≥0.99 for ambiguous cases.

## How to work on a change

1. Read `AGENTS.md` + the relevant package module.
2. Add/adjust unit tests under `tests/`.
3. Run: `python -m pytest tests/ -q`
4. Update docs if public API or CLI changes (`docs/README.md`, CHANGELOG, skill).
5. Bump version only when releasing.

## Generator (`partest-gen`)

| Command | Purpose |
|---------|---------|
| `init` | Monorepo skeleton; optional `--openapi` + G2–G4 |
| `from-openapi` | Skeleton + IR + resources (`--depth`) |
| `sync-openapi` | Refresh generated resources in existing project |
| `dump-ir` | OpenAPI → SuiteIR JSON |
| `init-ui` | **G5** deep UI tree on existing project |

Depth:

| `--depth` | Output |
|-----------|--------|
| `resources` | G2 paths + collections |
| `default` | + G3 payloads/validations + Default/NotAllowed |
| `p1` | + G4 full P1 stubs + checklist |

UI is **orthogonal** to depth: `--with-ui` on init, or `partest-gen init-ui`.

### Generator code ownership

| Module | Role |
|--------|------|
| `ir.py` | SuiteIR / OpIR from OpenAPI |
| `emitters/paths.py` | `paths.py` |
| `emitters/collections.py` | collection façades |
| `emitters/payloads.py` | BaseRequestBody modules |
| `emitters/validations.py` | pydantic validators |
| `emitters/tests_default.py` | G3 Default / 405 |
| `emitters/tests_p1.py` | G4 P1 stubs |
| `emitters/resources.py` | orchestrator |
| `ui_layout.py` | G5 UI tree |
| `skeleton.py` | root monorepo + optional UI |

Generated files with banner `AUTO-GENERATED by partest-gen` are safe to overwrite
on sync. Hand-edited files without the banner are skipped unless `--force`.

## Distribution

| Channel | Policy |
|---------|--------|
| **PyPI** | only public channel (`pip install partest` / `partest[ui]`) |
| Public GitHub | **not planned** — do not add source dump / Actions / public CI |

Wheel cookbooks live in `partest/docs/` (copy from `docs/` when user-facing files change).  
Do not put private stand URLs or absolute local paths in files that ship in the wheel.

Greenfield: `docs/QUICKSTART.md`. Cookbooks: REPORTING, SECURITY, UI_QUICKSTART, RECIPES.

```python
from partest.security import SecHttp, build_tampered_set
from partest.http import Config
from partest.ui import BasePage, attach_monitor, compare_images  # partest[ui]
```

## Consumer switch (aqa-like projects)

After **1.5.0** on PyPI:

1. Depend on `partest>=1.5.0` (+ `partest[ui]` for UI suite)
2. Replace local tracking / allure_helper / base_payload / validators / token manager / SecHttp / UI utils (`BasePage`, `PageMonitor`, `Storage`)
3. Keep domain: paths values, entity payloads, RBAC roles, page objects, DB cleanup, baselines
4. `partest-gen sync-openapi` / `init-ui` for new services; respect AUTO-GENERATED banner
5. aqa remaining: **W4 pin 1.5.0** + AQA-6 (`docs/RELEASE_1.5.0.md` §4)

```bash
python -m partest.project_gen.cli from-openapi /tmp/demo --file tests/fixtures/sample_openapi.yaml --depth p1 --force --with-ui
python -m partest.project_gen.cli init-ui /tmp/demo --force
python -m partest.ui.capture_baselines --dry-run
```
