# Цель этого файла — аудит зависимостей, а не установка.
#
# Ставится пакет через `pip install partest` (или `-e .`), и состав зависимостей
# объявлен в `setup.py`. Но `pip-audit` читает зависимости только из `pyproject.toml`
# или из `requirements.txt`: объявленные императивно в `setup.py` он статически не
# видит и честно отвечает «не проверено». Тот же приём и по той же причине у
# `partest-load`.
#
# Здесь перечислено всё, что пакет приносит потребителю: обязательное из
# `install_requires` и необязательное из extra `ui` и `gen`. Extra `dev` сюда не
# попадает намеренно — это средства разработки, потребителю они не едут, и аудит
# должен отвечать на вопрос «безопасно ли то, что уезжает», а не «чем мы тут
# пользуемся». Границы — те же, что в `setup.py`, строка в строку: расхождение
# ловит `tests/test_packaging.py`.
#
# Чем этот файл был до 2.1.0: списком закреплённых версий, который ничему не
# соответствовал. `python-dotenv` в нём не было вовсе — значит уязвимость в нём
# аудит не видел никогда и отчитывался зелёным; `Pillow` не было тоже; зато был
# двадцать один посторонний пакет (транзитивные плюс `ruff`, `pytest-repeat`) и
# заброшенный `py==1.11.0`. Список, разошедшийся с объявленным, хуже
# отсутствующего: аудит идёт, отчитывается зелёным и проверяет не то, что ставится.
